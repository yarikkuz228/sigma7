## Неисправность № 1 — среднее считается целочисленно

- Нарушенное правило из README: `average <показания...>` — среднее арифметическое всех показаний, дробная часть сохраняется.
- Команда и входные данные: `average 1 2`
- Ожидаемый результат: `average=1.5`
- Фактический результат до исправления: `average=1`
- Файл, метод, причина: `Sigma7/Telemetry.cs`, `Telemetry.Average`. Оба операнда выражения `sum / readings.Length` — целые, поэтому C# выполняет целочисленное деление и отбрасывает дробную часть ещё до возврата `double`.
- Исправление и объяснение: `return (double)sum / readings.Length;` — приведение одного операнда к `double` переводит деление в вещественное.
- Проверка после исправления: `average 1 2` → `average=1.5`; `average 10 20 30` → `average=20`.
- Дополнительный граничный случай: `average -1 -2` → `average=-1.5` (до исправления было `-1`: отбрасывание идёт к нулю, а не к ближайшему целому); `average 1 1 2` → `average=1.33333333333333`.

## Неисправность № 2 — тревоги не считают показания, равные порогу

- Нарушенное правило из README: `alarms` — тревога для каждого показания, которое **больше или равно** порогу.
- Команда и входные данные: `alarms 50 20 50 80`
- Ожидаемый результат: `alarms=2` (порог 50, показания 50 и 80)
- Фактический результат до исправления: `alarms=1`
- Файл, метод, причина: `Sigma7/Telemetry.cs`, `Telemetry.CountAlarms`. Условие `reading > threshold` строгое, поэтому показание, равное порогу, не попадает в счётчик.
- Исправление и объяснение: `if (reading >= threshold)` — нестрогое сравнение, как требует ТЗ.
- Проверка после исправления: `alarms 50 20 50 80` → `alarms=2`.
- Дополнительный граничный случай: `alarms 0 -100 0 100` → `alarms=2` (до исправления `1`); `alarms -100 -100` → `alarms=1`.

## Неисправность № 3 — минимум не учитывает последнее показание

- Нарушенное правило из README: `minimum <показания...>` — минимальное значение среди **всех** показаний.
- Команда и входные данные: `minimum 5 3`
- Ожидаемый результат: `minimum=3`
- Фактический результат до исправления: `minimum=5`
- Файл, метод, причина: `Sigma7/Telemetry.cs`, `Telemetry.Minimum`. В цикле `for (int i = 1; i < readings.Length - 1; i++)` правая граница уменьшена на единицу, поэтому последний элемент массива не проверяется; если он и есть минимум, результат остаётся от предыдущих элементов.
- Исправление и объяснение: `for (int i = 1; i < readings.Length; i++)` — цикл проходит все элементы, начиная со второго (первый уже взят как начальный минимум).
- Проверка после исправления: `minimum 5 3` → `minimum=3`; `minimum 2 8 7` → `minimum=2`.
- Дополнительный граничный случай: `minimum 5 4 3` → `minimum=3` (до исправления `4`); массив из одного элемента `minimum 7` → `minimum=7`.

## Неисправность № 4 — заправка затирает запас вместо прибавления

- Нарушенное правило из README: `refuel <запас> <добавка>` — создать бак с указанным запасом, затем добавить топливо к имеющемуся запасу; вывести новый запас.
- Команда и входные данные: `refuel 15 10`
- Ожидаемый результат: `fuel=25`
- Фактический результат до исправления: `fuel=10`
- Файл, метод, причина: `Sigma7/FuelTank.cs`, `FuelTank.Refuel`. Присваивание `Fuel = amount` заменяет текущий запас добавкой, а не увеличивает его.
- Исправление и объяснение: `Fuel += amount;` — к текущему запасу прибавляется количество топлива.
- Проверка после исправления: `refuel 15 10` → `fuel=25`; `refuel 0 15` → `fuel=15`.
- Дополнительный граничный случай: `refuel 100 0` → `fuel=100` (до исправления `0`; нулевая добавка не должна менять запас); `refuel 0 0` → `fuel=0`.

## Неисправность № 5 — имя члена экипажа не сохраняется

- Нарушенное правило из README: `crew <имя>` — свойство `Name` должно точно хранить переданное имя.
- Команда и входные данные: `crew "Анна Вега"`
- Ожидаемый результат: `crew=Анна Вега`
- Фактический результат до исправления: `crew=UNKNOWN`
- Файл, метод, причина: `Sigma7/CrewMember.cs`, конструктор `CrewMember`. Параметр `name` игнорируется, свойству `Name` присваивается строковый литерал `"UNKNOWN"`.
- Исправление и объяснение: `Name = name;` — в свойство записывается именно переданное имя, включая пробелы внутри.
- Проверка после исправления: `crew "Анна Вега"` → `crew=Анна Вега`.
- Дополнительный граничный случай: `crew " Анна "` → `crew= Анна ` (пробелы по краям сохраняются, до исправления `UNKNOWN`).

## Неисправность № 6 — шлюз открывается по одному фактору

- Нарушенное правило из README: `access <пропуск> <PIN>` — открыть шлюз только при одновременной успешной проверке пропуска **и** PIN.
- Команда и входные данные: `access 1 0`
- Ожидаемый результат: `access=CLOSED`
- Фактический результат до исправления: `access=OPEN`
- Файл, метод, причина: `Sigma7/Airlock.cs`, `Airlock.CanOpen`. Возвращается `validBadge || validPin`, то есть достаточно любого одного верного фактора.
- Исправление и объяснение: `return validBadge && validPin;` — логическое «И» требует успешной проверки обоих факторов.
- Проверка после исправления: `access 1 0` → `access=CLOSED`; `access 0 1` → `access=CLOSED`; `access 1 1` → `access=OPEN`.
- Дополнительный граничный случай: `access 0 0` → `access=CLOSED` (до исправления тоже `CLOSED`, поэтому основной контрпример — `access 0 1`).
